# Domain Model: Customers

## CustomerModel
**File:** `lib/models/customer_model.dart`

### Fields
| Field | Type | Default | Notes |
|---|---|---|---|
| `id` | `String` | required | Firestore document ID |
| `name` | `String` | required | Display name |
| `phoneNumber` | `String` | required | Free-form — no format validation |
| `pendingReturnAmount` | `double` | `0.0` | Unspent sales return credit owed to customer |
| `createdAt` | `DateTime` | required | |
| `updatedAt` | `DateTime` | required | Updated on any field change |
| `totalSpent` | `double` | `0.0` | Denormalized: sum of all `adjustedTotal` from posted invoices |
| `totalPaid` | `double` | `0.0` | Denormalized: sum of all `amountPaid` across invoices |
| `invoiceCount` | `int` | `0` | Denormalized: count of posted invoices |
| `lastPurchaseDate` | `DateTime?` | null | Date of most recent posted invoice |

### Computed Getters
| Getter | Formula | Notes |
|---|---|---|
| `outstandingAmount` | `totalSpent - totalPaid` | Negative = customer has credit balance |

### Important Notes on Denormalized Fields
- `totalSpent`, `totalPaid`, `invoiceCount`, `lastPurchaseDate` are written on every invoice create/edit/cancel
- They are NOT recalculated from scratch on read — they accumulate via increments/decrements
- No periodic reconciliation job exists — drift is possible if a write fails mid-operation
- `outstandingAmount` can go negative if `totalPaid > totalSpent` (overpayment scenario)

## PaymentRiskModel
**File:** `lib/models/payment_risk_model.dart`

| Field | Type | Notes |
|---|---|---|
| `customerId` | `String` | FK → customers/{customerId} |
| `riskScore` | `double` | 0–100 (100 = highest risk) |
| `riskLevel` | `String` | `'critical'` \| `'high'` \| `'medium'` \| `'low'` |
| `totalOutstanding` | `double` | Total amount owed by customer |
| `overdueInvoices` | `int` | Count of invoices past follow-up date |
| `maxDaysOverdue` | `int` | Days since oldest unpaid invoice's follow-up date |
| `paymentReliability` | `double` | Historical on-time payment ratio (0–1) |
| Risk factors | `List<Map>` | Each factor has name, impact score, description |

Recommendations generated by AI or fallback:
- `'critical'` → "Call immediately"
- `'high'` → "Follow up within 2-3 days"  
- `'medium'` → "Send WhatsApp reminder"
- `'low'` → "Monitor next invoice"
